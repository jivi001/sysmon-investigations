## 1. Objective

Learn to inspect Windows telemetry, investigate Sysmon process-creation events, correlate parent-child processes, and document findings without making unsupported security conclusions.

## 2. Key Concepts

- **Windows Security logs:** Record security-related events generated by Windows auditing. Event ID 4625 represents a failed logon when the relevant event is generated and retained.
- **Sysmon:** Provides detailed system activity telemetry, depending on its configuration. It is a telemetry source, not an antivirus verdict engine.
- **Sysmon Event ID 1:** Records process-creation activity.
- **PID:** Identifies a process during its lifetime but can be reused.
- **ProcessGuid:** Helps identify and correlate a Sysmon process instance.
- **ParentProcessGuid:** Helps correlate a child event with its recorded parent process instance.
- **SIEM ingestion:** Events present on an endpoint are not necessarily ingested or indexed by the SIEM.

## 4. Process-Tree Investigation

The observed `cmd.exe` event recorded:

- Parent image: `C:\WINDOWS\system32\svchost.exe`
- Parent PID: `1348`
- Parent GUID: `{200c15b6-810d-6ad4-1a00-000000001600}`
- Command line executing: `C:\WINDOWS\system32\hpatchmonTask.cmd`
- User: `NT AUTHORITY\SYSTEM`

A separate `taskhostw.exe` event recorded the same parent PID and GUID. Other events, including `TiWorker.exe` and `unsecapp.exe`, recorded parent PID `952` and parent GUID `{200c15b6-810c-6ad4-0d00-000000001600}`.

The parent command line included `-s Schedule`, indicating association with the Windows Task Scheduler service. The `hpatchmonTask.cmd` execution warrants investigation, but the available evidence does not establish that it is malicious.

## 5. Query Validation Lesson

An earlier query searched event-message text for `ProcessGuid`. This could incorrectly match `ParentProcessGuid`, because the latter contains the same substring.

The improved method parses the event's structured XML and compares the event's own `ProcessGuid` against the target GUIDs using exact equality.

The corrected query returned no output for either target GUID within the newest 1,000 queried Event ID 1 records.

**Interpretation:** The original parent events were not found in that queried set. They may be outside the query window, no longer retained, or absent from the collected telemetry. The reason remains undetermined.

## 6. Investigation Principles Learned

1. Validate the telemetry source before investigating.
2. Use structured event fields instead of fragile text matching.
3. Prefer process GUIDs over PID-only correlation.
4. Use timestamps and surrounding evidence to build a process timeline.
5. Treat suspicious command lines as investigation leads, not proof of compromise.
6. Document confirmed observations separately from hypotheses and unresolved questions.
7. Treat an empty query result as a bounded finding, not proof that an event never existed.

## 7. Final Conclusion

Lesson 1 established the fundamentals of Windows telemetry and Sysmon process-creation analysis. I learned how to retrieve Event ID 1 records, interpret process and parent fields, understand process identity correlation, and recognize a query-validation flaw.
